# Support

Zee uses different public routes for conversation and actionable engineering
work. Choosing the right one keeps support approachable without turning the
issue tracker into a general forum.

## Questions, feedback, and compatibility reports

Use [GitHub Issues](https://github.com/OWNER/Zee/issues/new/choose) for:

- setup and everyday-use questions;
- early feature ideas and design discussion;
- website, media, authentication, or extension compatibility experiences;
- feedback that still needs other users to compare devices or workflows; and
- release announcements and broader project conversation.

Issues are public. Remove passwords, account details, private URLs, browsing
history, personal messages, and other sensitive information before posting.

## Reproducible bugs and planned work

Use [GitHub Issues](https://github.com/OWNER/Zee/issues/new/choose) when a
report has a Zee version, Apple platform, repeatable steps, expected result,
and actual result. Search existing issues first and add sanitized evidence only
when it changes what another person can reproduce.

The [roadmap](Documentation/ROADMAP.md) and
the [release milestones](https://github.com/OWNER/Zee/milestones) are the
public view of currently planned outcomes. Only the maintainer adds items to
them, so opening an issue doesn't put it on the roadmap. Scope may evolve as
engine and physical-device validation clarify the correct behavior.

## Security vulnerabilities

Use GitHub's
[private vulnerability report](https://github.com/OWNER/Zee/security/advisories/new).
Do not post suspected vulnerabilities in a public issue. See
[SECURITY.md](SECURITY.md) for scope and reporting guidance.
